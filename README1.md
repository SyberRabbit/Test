# 求助：ICMP 全通 0% 丢包，但 TCP 全端口超时（VLESS Reality / DMIT）

> 环境：macOS + mihomo (Clash Verge Rev)，节点为自建 VLESS + Reality（偷自己域名）。
> 出口运营商：**中国移动（北京）**，公司/园区大内网。
> 现象：节点**间歇性**不可用，故障期约 6～7 分钟，随后自行恢复。

---

## 一、核心矛盾（最想请教的点）

同一时刻，对同一台服务器：

| 检测项 | 故障节点 A | 对照节点 B |
|---|---|---|
| ICMP ping | ✅ **5/5 通，0% 丢包，158ms，TTL 46** | ✅ 3/3 通，154ms |
| TCP 443 | ❌ 连续 5 次 `Operation timed out` | ✅ 成功 |
| TCP 80 | ❌ 超时 | ⚠️ `Connection refused`（有 RST） |
| TCP 22 | ❌ 超时 | — |
| TCP 8080 | ❌ 超时 | — |

**关键点：**

1. 节点 A **所有端口一律超时**，连 RST 都收不到 → 不是「443 被针对性阻断」，而是整个 IP 的 TCP 被黑洞
2. 节点 B 的 80 端口能回 **Connection refused（RST）** → 证明本机 TCP 栈健康、能正常收到对端响应
3. ping 延迟 158ms、抖动仅 0.73ms、丢包 0% → **链路质量本身完全正常**，坏的是「可达性」而非「质量」
4. SYN 等待完整 10 秒后超时，无任何字节返回

### 我的读法

- 两条路径**前 13 跳完全一致**，共用同一个移动国际出口 `223.120.161.6 / 223.120.197.2`，到此处均为 154ms 正常
- 分歧在之后：故障节点的包**成功进入了 `193.41.250.0/24` 对端网络**，并在其中走了 6 跳，其中 `193.41.250.86` **重复出现两次**，但始终到不了目标主机
- 推测：**对端网络内部的路由环路 / 转发异常**。中途每跳都能回 TTL-exceeded（所以 ping 通、能看到 158ms），但承载 TCP 的转发路径到不了目的主机，SYN 在这段被吞掉 → 纯超时、无 RST、且与端口无关

## 六、最难解释的一点（求网友指点）

**同一局域网内的 Windows 笔记本，在 Mac 超时的同一时间却能正常连接。**

两台机器：
- 同一局域网、同一网关
- 出口公网 IP 相同（均为该移动大内网 NAT 出口）

我目前的推测：

1. 这是**路由层的间歇性异常**，不按源地址过滤，因此不是「源 IP 被封」
2. Windows 若当时已有 **ESTABLISHED 长连接**，则无需新建 SYN，故障期内可继续通信
3. 故障具有**时间性**（09:28 坏 → 09:40 好 → 14:35 又坏），两台机器测试若相差数十秒，结论就可能不同

但我没能在两台机器上做到**严格同一秒**的对比测试，所以不敢完全确定。
